# 생성기 입력

UTF-8 JSON 파일 하나에 아래 세 필드를 담아라.

```json
{
  "source": "사용자가 제공한 원문 그대로. 40~24000자.",
  "kind": "symposium",
  "draft": {
    "title": "제목",
    "summaries": ["제목을 보충하는 요약"],
    "lead": "첫 문단",
    "paragraphs": ["상세 내용 첫 문단", "후속 조치 문단"],
    "tables": [],
    "metadata": {"releaseAt": "", "distributedAt": "", "department": "", "manager": "", "contact": ""},
    "evidence": [{"claim": "초안의 핵심 주장", "sourceQuote": "그 주장을 뒷받침하는 원문의 정확한 구절"}],
    "missingFacts": ["배포 시점 확인 필요"]
  }
}
```

예시의 설명 문구를 실제 내용으로 모두 교체하라.
JSON 문자열 내부 줄바꿈은 `\n`으로 표현하라. 원문은 원문대로 유지하고 가상의 보도자료 내용을 source에 추가하여 검사를 통과시키지 말라. 사용자가 별도로 제공한 추가 사실만 원문에 명확히 병합할 수 있다.

`kind`는 `symposium`(교육·행사 포함), `statistics`, `program`, `research`, `general` 중 하나다.

제목은 110자 이하, 요약은 1~3개·각 150자 이하, 첫 문단은 700자 이하, 본문은 2~24문단·각 1200자 이하다. 이 제한은 최대치이며 길게 쓰라는 목표가 아니다. 본문과 표를 합쳐 16000자 이내로 작성하라. 의미를 보존한 퇴고로도 초과하면 문서를 나누는 방안을 사용자에게 설명하라.

`metadata`의 빈 값은 HWPX에서도 빈칸으로 남는다. `missingFacts`는 문서 생성용 메타데이터가 아니라 별도 확인 목록이다. 문서 안에 불필요한 내부 검토 문구를 본문으로 삽입하지 말라.

표는 다음 구조를 사용하라. `afterParagraph: 0`은 첫 문단 뒤, `1`은 paragraphs의 첫 문단 뒤다.

```json
{"caption": "표 제목", "columns": ["항목", "내용"], "rows": [["원문의 항목", "원문에 근거한 내용"]], "afterParagraph": 1}
```

표는 최대 3개, 각 표는 2~6열·데이터 1~15행이다. 같은 표의 모든 행은 열 수가 같아야 한다. 표 제목과 열 이름을 새 숫자나 임의의 연도로 꾸미지 말라.

`evidence`는 1~60개로, 제목·요약·본문·표의 핵심 주장 각각에 근거를 연결하라. `claim`은 500자 이하, `sourceQuote`는 900자 이하의 원문 구절이다. 실제 원문 표현을 복사하고 그 뜻을 바꿔서는 안 된다. 원문 밖의 지식을 넣고 나중에 근거처럼 원문을 수정하지 말라.
