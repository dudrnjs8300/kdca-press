# 원문과 생성물 처리

v0.2 기본 경로는 영구 문서함을 만들지 않습니다.

| 정보 | 보관 위치와 기간 |
| --- | --- |
| Skill에 입력한 원문·결과 | 이용 중인 AI 서비스의 실행 환경·대화; 해당 서비스 정책 적용 |
| 원격 MCP 원문·초안 | 요청 처리 메모리; 문서 DB에 기록하지 않음 |
| 원격 생성 HWPX·본문·검사·미리보기 | 메모리, 30분 또는 재시작 중 먼저 발생하는 때까지 |
| GitHub 인증·OAuth 상태 | 메모리 SQLite; 재시작 후 사라짐 |
| 소스 저장소 | 프로그램·가상 examples/evals; 실제 업무 문서 업로드 기능 없음 |

MCP 다운로드 URL의 긴 무작위 토큰은 파일 접근 권한입니다. 링크를 전달한 사람도 만료 전 파일을 받을 수 있습니다. MCP resource 읽기는 생성한 사용자에게만 허용합니다. 토큰은 해시로 보관하며 다운로드 응답은 no-store/noindex, 미리보기는 sandbox 정책을 적용합니다. 서버가 지워도 사용자가 내려받은 파일과 AI 대화 사본이 삭제되지는 않습니다.

인증에는 GitHub 로그인, PKCE, 제한된 redirect 검증과 일회성 인증 코드를 사용합니다. 공개 운영에는 HTTPS와 비밀 환경 변수가 필요합니다. 허용할 GitHub 숫자 ID를 제한할 수 있습니다. 로컬 데모 인증은 loopback 개발 환경으로 제한합니다.

원문 최대 24,000자, JSON 입력 크기 제한, 생성 subprocess 시간·동시 실행 제한, 메모리 생성물 수·용량 한도, 요청 속도 제한을 적용했습니다. 미리보기 worker도 별도 시간·메모리 제한을 둡니다. 공개 입력을 사용하더라도 서비스 제공자의 보관 정책은 별도로 적용됩니다.

본문·토큰을 의도적으로 애플리케이션 로그에 기록하지 않습니다. 호스팅 제공업체의 프록시 접근 로그에 URL이 기록될 수 있으므로 운영 환경에서 다운로드 쿼리의 로깅 정책을 확인해야 합니다. 외부 주소를 자동으로 가져오는 도구는 없습니다.

자동 검사는 사실 확인의 보조 수단입니다. 동일 수치의 대상 바꿔치기, 미묘한 인과·부정 의미 변경을 전부 검출하지 못합니다. Skill은 원문을 지시문으로 취급하지 않고 자료로 다루며, 핵심 주장과 수치를 직접 대조하도록 요구합니다.

`src/app.js` 등 v0.1 프로토타입은 SQLite 문서 저장 기능이 있습니다. 이는 `npm start`, 배포 Dockerfile, v0.2 MCP에 사용하지 않습니다. 예전 코드를 별도로 실행할 때는 이 메모리 전용 설명을 적용할 수 없습니다.
